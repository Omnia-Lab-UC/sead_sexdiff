# Proposal

## Why

The primary analysis (`reports/motco-astrocyte-2026-10-19.md`, archived change `2026-10-19-mtg-astrocyte-motco-analysis`) and the forced-rank sweep (`reports/motco-astrocyte-rank-sensitivity-2026-10-19.md`, archived change `2026-10-19-mtg-astrocyte-rank-sensitivity`) both leave the preprocessing choices of the export as fixed choices whose sensitivity analysis is a follow-up (primary report §7 "Preprocessing choices", §8). The first of those choices is the removal of chrX, chrY and chrM features before any filtering: it was chosen because sex is the group and X-dosage features would separate the sexes trivially, and the export's `features_<omic>.csv` status column was designed to make it reversible (archived export design, Risks). Nothing in this repo yet measures whether the primary result depends on it. Of the three preprocessing axes the reports list (other N, keeping chrX, residualized features), the decision on 2026-10-19 is to run only the chrX axis now: other N values are out of scope, and residualized features are deferred because the current covariate handling (exported, applied inside MOTCO's analysis) is preferred.

## What Changes

- **New `preprocessing-sensitivity` step.** For each cohort (`cohort_30` primary, `cohort_50` sensitivity) and each variant of a predeclared registry, `PREPROCESSING_VARIANTS`, rerun the export with one setting changed and then the covariate-adjusted analysis unchanged, and compare the result with the primary analysis. The registry holds one variant, `keep_chrx`: excluded chromosomes `chrY` and `chrM` instead of `chrX`, `chrY`, `chrM`. Every other export setting (cohort donors, `k` from the smallest sex × stage cell, CPM ≥ 1 in ≥ k donors, TMM, prior count 2, top 5,000 by variance per omic, GENCODE v32 basic) and every analysis setting (blocks, stage order, the six covariates in order, missing policy `error`, net-displacement orientation, CV rank selection at MOTCO's defaults, 999 permutations, seed `20261019`) is equal to the primary pipeline. The variant is the primary pipeline with chrX kept, not the primary blocks with chrX features appended: library sizes, the abundance filter, TMM factors, log2-CPM and the variance ranking are all recomputed with chrX present, and chrX features compete for the 5,000 slots like any other feature.
- **The primary export and analysis are the reference, read and checked, never rerun.** Before anything is written the step checks that the primary export in `results/motco_input/<cohort>/` was made from the pseudobulk and annotation now on disk and with the thresholds the constants hold, and that the primary analysis in `results/motco_analysis/<cohort>/` matches that export (hashes), the installed MOTCO, the seed and the permutation count (the same check the rank sweep makes). Neither directory is written.
- **Outputs per variant** under `results/motco_sensitivity/<variant>/`: `motco_input/<cohort>/` (the variant export, the same seven files as the primary export, with `excluded_chromosomes = [chrY, chrM]` and the variant name in its manifest), `motco_analysis/<cohort>/` (the variant analysis, the same seven files as the primary analysis), and `comparison/<cohort>/` with `sensitivity.csv` (the primary row then the variant row: rank, `delta`, `angle`, `shape`, p-values, null summaries, CV AUROC), its Markdown rendering `sensitivity.md` (statistics tables plus the feature accounting: counts after each export step per omic, kept features on chrX, kept features shared with the primary) and `sensitivity_manifest.json` (variant settings, every input and reference hash, software, git revision, findings). The layout mirrors `results/motco_input/` and `results/motco_analysis/`, so the `rank-sensitivity` command can later be pointed at a variant without code changes.
- **A committed report** `reports/motco-astrocyte-chrx-sensitivity-<date>.md` with each cohort's comparison pasted from the generated files, checked against every `result.json` before commit, and the binding reading: the primary analysis stays primary; a rejection status that differs between the variant and the primary is preprocessing dependence, not a result of the variant; `angle`/`shape` non-rejections stay uninformative and a `delta` rejection is a difference, not specifically of size; a CV-selected rank that differs is reported beside `angle`; with chrX kept, features whose expression or accessibility differs between the sexes by dosage enter the blocks, and MOTCO's operating characteristics were not measured with such features, so the variant carries no Type I or power claim of its own.
- The export's per-cohort body moves into a shared helper so that the variant export is the primary export with one setting changed; `export` output stays byte-identical. README and AGENTS.md document the command, the registry and the reading rules.

Out of scope, as later changes: other N values and residualized features (deferred by decision on 2026-10-19; the registry can take them later); a selection-rule variant (trend-corrected variance or a ribosomal/mitochondrial exclusion list), suggested by the uncommitted 2026-10-19 diagnostic that found the primary's rank-1 PLS axis tracking ribosomal-protein and ferritin genes and the TMM factor; the forced-rank sweep on the variant; pathway/module enrichment; any MOTCO-side change.

## Impact

- `src/sead_sexdiff/data.py`: new constants `PREPROCESSING_VARIANTS` and `PREPROCESSING_SENSITIVITY_*` (output names), a refactor that moves the per-cohort body of `run_export` into a shared helper taking the excluded chromosomes as a parameter (`run_export` output must stay byte-identical), a `_check_export_reference` beside the existing `_check_reference`, `run_preprocessing_sensitivity`, a comparison row builder reusing `_sensitivity_row` with a leading `variant` column (the rank sweep's `rank_sensitivity.csv` is unchanged) and `render_preprocessing_sensitivity`. `_analyze_cohort` is reused as is with CV parameters.
- `src/sead_sexdiff/cli.py`: new `preprocessing-sensitivity` subcommand (`--variant`, `--cohort`, `--pseudobulk-dir`, `--input-dir`, `--analysis-dir`, `--out-dir`, `--data-root`, `--n-jobs`, `--force`). The registry is a constant, not a flag.
- `reports/`: one new committed report. `results/` stays gitignored.
- No dependency change: MOTCO 0.8.0 and the existing export code cover the variant.
- Compute: one export (seconds) and one CV analysis (about a minute) per cohort and variant. The variant export needs `results/pseudobulk/` and the GENCODE GTF; the machine this change is proposed on (`nixos-home`) holds `results/motco_input/` and `results/motco_analysis/` but neither of those, so the real run needs `scripts/sync_pseudobulk.sh` and the one-time annotation download first (internet is available there), or the workstation that ran the primary export.
- Scientific choices introduced here (flag and ask before changing): the variant registry `PREPROCESSING_VARIANTS` with `keep_chrx` removing only `chrY` and `chrM`; the variant reruns the whole export pipeline at the primary's thresholds and N; the analysis settings are the primary's; `n_jobs = 1` for the reported results; and the rule that the primary analysis stays primary.
