# Design

## Context

See proposal.md — Why. The pieces already exist: raw donor × feature counts in `results/pseudobulk/{rna,atac}_counts.h5ad` (`obs`: `sex`, `stage`, `n_rna`, `n_atac`, cohort flags), the export's per-feature status tables (`features_<omic>.csv`: `sex_chromosome` / `abundance` / `variance` / `kept`), the export's `covariates.csv` and `metadata.csv`, the primary analysis's `result.json`, the reference check `_check_reference` (analysis ↔ export hashes, MOTCO version, seed, permutations) and the export's own `preprocess_block` (reused for the pseudobulk ↔ export binding, D8; `check_export_inputs` compares no hash and is not called). pydeseq2 0.5.3 is pinned (`DeseqDataSet(counts=..., metadata=..., design=<formula>)`, `DeseqStats(contrast=<vector>)`, Wald only; its `continuous_factors` and `ref_level` arguments are deprecated and have no effect). The legacy PFC `differential_expression` uses pydeseq2 on a cell × supertype pseudobulk with a hard-coded contrast vector; it is left alone.

## Goals / Non-Goals

**Goals:**
- One function, `run_stage_de`, that fits the four registered models per cohort × omic on the export-bound feature set, writes one table per tested coefficient, a summary and a manifest, evaluates the concordance rule, and reads the astrocyte directories by default but any cell-type root through its directory arguments.
- Every number in the report traceable to a generated file.

**Non-Goals:**
- A joint test of the two factor-interaction coefficients (no LRT in pydeseq2 0.5.3).
- Effect-size shrinkage, enrichment, peak-to-gene links, plots.
- Using the DE results anywhere upstream.

## Decisions

- **D1 — Feature set from `features_<omic>.csv`, not recomputed.** The step reads the export's status table and keeps `variance` + `kept`, in the export's order. Alternative: redo the chromosome and abundance filter from the annotation. Rejected: it would duplicate the export's code path and need the GTF; the status table is hash-bound to the pseudobulk through the export manifest, so reading it binds the DE to the exact primary filtering.
- **D2 — DESeq2's own normalization on the abundance-passing set.** Size factors (median of ratios) and dispersions are fitted on the ~20k genes / ~125k peaks that passed abundance, not on MOTCO's 5,000 or on all 36,601 / 218,882 features. Alternative: all raw features. Rejected: thousands of all-zero or near-zero peaks and the sex-chromosome genes would enter the dispersion trend. The TMM factors of the export are not reused: DESeq2 is its own method and the manifest says so.
- **D3 — Design formulas through pydeseq2's formula interface.** `design="~ sex + stage + sex:stage + age_at_death + pmi + rin + years_education + log10_n_rna"` and nothing else: the covariates and `stage_num` are continuous because they are float columns of the design table, and `sex` and `stage` are unordered pandas categoricals whose first category is the reference level (`STAGE_DE_REFERENCE_LEVELS`), so the treatment-coded design columns are `sex[T.Male]`, `stage[T.1]`, `stage[T.2]`, `sex[T.Male]:stage[T.1]`, `sex[T.Male]:stage[T.2]` (amended at apply time: pydeseq2 0.5.3's `continuous_factors` and `ref_level` are deprecated and have no effect). Each tested coefficient is a unit contrast vector on `dds.obsm["design_matrix"].columns`, located by column name, never by position; the registry holds the expected names, a name that is not found exactly is an error, and the resolved columns are recorded in the fit records and the manifest. Before anything is written each model's design matrix is built as pydeseq2 builds it (`FormulaicContrasts`), checked for full rank and its tested columns resolved (`stage_de_design_check`), so a rank or naming error stops the step before any fit. Verified at tasks 2.1–2.2 on a synthetic dataset.
- **D4 — Registry `STAGE_DE_MODELS`** maps model name → `{"formula": ..., "stage_coding": "factor" | "numeric", "tested": [(label, column), ...], "interaction": bool}`. `STAGE_DE_COVARIATES = {"rna": (..., "log10_n_rna"), "atac": (..., "log10_n_atac")}`. The union per factor model is computed in the summary, not as a fifth test.
- **D5 — Two reporting sets.** Every table carries `exported`; the summary counts on `exported` (primary) and `abundance` (all tested). `padj` is DESeq2's over all tested features, not recomputed on the exported subset, so the exported-set count is "features MOTCO measured that are significant in the full test", which is what the concordance rule needs.
- **D6 — Concordance rule** `STAGE_DE_CONCORDANCE_RULE` evaluated from `stage_de_summary.csv` rows (`factor_interaction`, union, `exported`) and the primary `result.json` (`p_values.delta ≤ ANALYSIS_ALPHA` under `ANALYSIS_REJECTION_RULE`, as the comparison tables derive the status; only the binary status enters the cell). Written into the `interaction_detected`, `delta_rejected` and `concordance` cells of each omic's `factor_interaction` / `union` / `exported` row of the cohort's summary (empty on every other row) and into the manifest. The rule names only the factor model, so the trend model's interaction count is reported beside it but does not enter the rule.
- **D7 — Layout and flags.** `results/stage_de/<cohort>/<omic>/<model>__<coefficient>.csv`, `<omic>/<model>__fit.json` (the fit record, added at apply time: a fingerprint of the inputs' sha256 and the settings, the fit, the reproduction of the export and each table's sha256), `stage_de_summary.csv` (one per cohort), `stage_de.md`, `stage_de_manifest.json`. A model is skipped without `--force` only when its record's fingerprint equals the current one, the record carries every part the summary reads and its tables hash as recorded; a table without a matching record is refit; a record made from other inputs or settings, or unreadable, is an error (also for an omic not requested in the run). CLI: `--cohort`, `--omic {rna,atac,both}`, `--pseudobulk-dir`, `--input-dir`, `--analysis-dir`, `--out-dir`, `--n-cpus`, `--force`. `--n-cpus` does not change the tables (task 3.3 checks `pvalue` and `padj`); warnings raised in pydeseq2's worker processes are not captured when it is above 1, which the fit records (`warnings_scope`) and the findings say.
- **D8 — Reference checks reused.** The export manifest's `input` block records the sha256 of the pseudobulk `manifest.json` (and of the covariates manifest), not of the count files, and neither the pseudobulk manifest nor any other manifest records both count files' hashes (amended 2026-10-21 by decision of the user, at apply time). So the pseudobulk ↔ export check is a hash comparison of `manifest.json` against `input.pseudobulk_manifest_sha256`, plus a reproduction: `preprocess_block` (the export's own code path) is rerun on the cohort donors' counts with the chromosomes of `features_<omic>.csv` (no GTF) and the recorded thresholds and `k` (the TMM trims and the float format are the module constants; the recorded ones must equal them, otherwise the step stops naming the setting). The statuses must equal `features_<omic>.csv` and the per-donor `lib_size_filter` / `lib_size` the manifest's `tmm` block exactly. The TMM factors must match to rounding (rtol 1e-10), and every tested feature's log2-CPM variance (`features_<omic>.csv` `variance`) and the exported values `rna.csv` / `atac.csv` to the export's float format (rtol 1e-9), so a count change confined to tested-but-not-exported features is caught too. It is still not a hash: a change that leaves all of these unchanged would pass. Any difference names the count file and the `export` command. The cohort donors, sex and stage are cross-checked between `metadata.csv`, `donor_table.csv` and the count files' `obs`. The sha256 of every file read, the count files included, goes to the manifest. `_check_reference` covers the analysis. Every check runs for every requested cohort before any fit, and the step writes nothing when one fails; every file is hashed before it is read and again after each cohort's fits (a change detected then stops the step after that cohort's tables and fit records, whose fingerprints carry the old hashes, and before its summary, Markdown and manifest).
- **D9 — Rendering.** `render_stage_de` writes `stage_de.md` from the summary and manifest only (counts table per omic, concordance table, covariates, models, findings), so the report can paste it.
- **D10 — R cross-check protocol (added at apply time).** `scripts/check_stage_de_deseq2.R` reads `run_stage_de(debug_dir=...)` files (counts, design and, per model fitted in that call, the trend, dispersions and size factors) and compares twice: a full `DESeq()` fit with the dispersion trend type pydeseq2 used (pydeseq2 switches a non-converged parametric trend to a mean trend, R's DESeq2 to a local one), and a plug-in Wald test on pydeseq2's size factors and dispersions. The 1e-3 tolerance of task 3.4 is evaluated on the features with fitted means ≥ 0.5 and a converged pydeseq2 LFC fit (DESeq2 floors mu at 0.5 in the standard errors; a non-converged IRLS was fitted by pydeseq2's fallback optimizer); the rest are counted apart, and every feature enters the comparison of the significant sets. Exit 0 both pass, 2 only the full fit's tolerance fails, 3 trend types differ, 4 another comparison fails, 1 an R error. The full comparison is not expected to pass: pydeseq2 0.5.3 lacks DESeq2's reset of non-improving gene-wise dispersion fits, so task 3.4 records the differences.

## Risks / Trade-offs

- [Two Wald tests per factor model inflate the union count] → the union is labelled as such in every output and the per-coefficient counts are always beside it; the concordance rule is predeclared on the union and the report says what that means.
- [ATAC: ~125k peaks × 4 fits is slow and memory-heavy in pydeseq2] → `n_cpus`; fits run one model at a time and free the `DeseqDataSet`; the step is resumable per cohort × omic × model (a model whose fit record matches is skipped without `--force`, D7).
- [DESeq2 normalization differs from the export's TMM] → recorded in the manifest and stated in the report; the feature set is the same, the normalization is DESeq2's by design (D2).
- [padj ≤ α is an approximate FDR] → DESeq2's Wald test plugs in estimated dispersions; on simulations under DESeq2's own model the realized FDR at padj ≤ 0.05 was about 0.06–0.09 (higher with few non-null features), so the report calls the counts approximate.
- [Cook's handling is inactive with continuous covariates] → no donor shares a design row, so no outlier is replaced or filtered (as in R's DESeq2); stated in the manifest and the report.
- [Interaction tests at n = 80 with cells of 9–28 have little power] → the report reads a zero interaction count as "none detected at this n", never as "no interaction"; the stage main-effect counts are the informative description.
- [pydeseq2 column naming or `ref_level` semantics differ from the assumption in D3] → resolved by name with an error on mismatch; checked on synthetic data before real data.

## Open Questions

None that change the specs or tasks. Whether `independent_filter` removes many low-count peaks is read from the output (`padj` NaN count, recorded in the manifest).
