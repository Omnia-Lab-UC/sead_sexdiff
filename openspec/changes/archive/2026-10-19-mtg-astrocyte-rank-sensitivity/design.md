# Design

## Context

See `proposal.md` for the motivation. The state that shapes the approach:

- **The analysis step** (`run_analysis`, archived change `2026-10-19-mtg-astrocyte-motco-analysis`) reads a cohort's export with `load_analysis_inputs`, builds `TrajectoryDataset` and `TrajectoryAnalysisParams(permutations=999, seed=ANALYSIS_SEED, n_jobs=n_jobs)`, calls `analyze_trajectories`, writes MOTCO's artifact with `write_analysis_outputs` into `<cohort>.tmp/`, adds `analysis_metadata.csv`, `summary.md` (`render_analysis_summary`) and `analysis_manifest.json` (input hashes, model, preprocessing, covariates, measurement incl. `forced_components: null`, `cli_equivalent`, software, git, findings), then renames. All of this is one function body; the forced runs need the same body with one parameter changed.
- **MOTCO 0.8.0 forced path** (`motco.simulations.evaluation.fit_pls_latent_space`, reached through `TrajectoryAnalysisParams.forced_components`): cross-validation is skipped entirely, the pooled PLS-DA is fitted at the requested rank, and the metadata records `component_selection = "forced"`, `selected_lv = k`, `cv_mean_auroc = None`, `cv_repeats_completed = 0` and `integration_params = {stage_col, selected_lv, forced_components}` (no CV knobs). The override is rejected, not clamped, outside `[2, min(n_features, n_samples)]`, so rank 1 cannot be forced. `motco analyze --forced-components K` exposes the same path. The record's `params` block carries `forced_components`.
- **Current records**: CV selected rank 1 in both cohorts (`cv_mean_auroc` 0.63 / 0.66), nothing rejected, `angle` 0° with p = 1. `max_feasible_components` is 80 (`cohort_30`) and 74 (`cohort_50`), so every ladder rank is feasible. The RRPP seed and the permutation count are constants; MOTCO's Type I study ran its forced-rank columns with the same constant seed as its CV column so that "every column draws the same permutation indices".
- **MOTCO's forced-rank evidence** (all without covariates): at the Phase 6 design (n = 80, K = 3, cells 11/10/28 vs 9/10/12) `pls_forced4 × nd` holds size on all three statistics (anchor `delta` 0.006, `angle` 0.048, `shape` 0.006; `net-displacement-type-i-2026-10-13.md` §2) with a narrower, less dispersed `angle` null than CV (q95 32.8° IQR 5.9 vs 12.1° IQR 26.6; §4); the orientation probe found `pls_forced` at rank 2(K − 1) = 4 recovers orientation (`angle` power 0.99 at e = 1) but drops `shape` power from 0.19 to 0.01 and leaks `angle` into the magnitude cell (0.15) (`orientation-measurement-probe-2026-10-12.md` §3, §6); the Phase 5 rank ladder (n = 1200, K = 4) found no `angle` gain above `n_stages − 1`, `shape` and `delta` power losses, a wider `angle` null, and no anchor inflation at any rank (`latent-rank-ladder-2026-09-08.md`). The covariate Type I check ran under CV only.
- **Where the data are**: `results/motco_input/` and `results/motco_analysis/` exist on the workstation that ran `analyze`; the machine this change was proposed on has neither, so code and synthetic checks happen anywhere, the real run there.

## Goals / Non-Goals

**Goals:**
- One command per cohort that produces the six forced-rank artifacts and the cross-rank table from the export and the existing analysis, with the same provenance discipline as `analyze`.
- The forced runs and the CV run share one code path, so a forced-rank directory is a CV directory with one setting changed and nothing else.
- `run_analysis` keeps producing byte-identical outputs (the archived change's reproducibility requirement) across the refactor.
- The report can only be read as sensitivity.

**Non-Goals:**
- Re-running the CV-selected analysis, or changing anything under `results/motco_analysis/`.
- A rank-selection rule, a "best rank", or any reading of the sweep that replaces the primary analysis.
- Any sensitivity axis other than the rank (preprocessing exports, residualized features: later changes).
- A pytest suite; verification stays synthetic checks plus the real run.

## Decisions

**D1. Extract the per-cohort body of `run_analysis` into a shared helper.**
`_analyze_cohort(cohort, cohort_dir, loaded, params, *, out_dir, final_name, n_jobs, findings)` builds the dataset, runs `analyze_trajectories`, writes the artifact, `analysis_metadata.csv`, `summary.md` and `analysis_manifest.json` into `<out_dir>/<final_name>.tmp/`, renames, and returns `{"dir", "record", "manifest", "findings"}`. `run_analysis` becomes the loop that loads each cohort, builds the CV `params` and calls the helper; `run_rank_sensitivity` loads each cohort once and calls the helper once per rank with `TrajectoryAnalysisParams(permutations=ANALYSIS_PERMUTATIONS, seed=ANALYSIS_SEED, n_jobs=n_jobs, forced_components=k)`. The manifest keeps every existing key; for forced runs `measurement.component_selection` is `forced`, `measurement.forced_components` is `k`, `measurement.cv` is `null` with a `cv_note` saying cross-validation was skipped, and `cli_equivalent` carries `--forced-components k` and omits the CV flags. The rank-1 finding and the capped-age and `n_jobs` findings stay in the helper so every directory carries them.
- *Alternative: a second function copying the body.* Rejected: two copies of the manifest and summary logic would drift, and the point of the sweep is that nothing but the rank differs.
- *Verification of the refactor:* on the synthetic dataset, run `run_analysis` before and after the refactor into two scratch directories; `latent_scores.csv`, `pls_loadings.csv`, `stage_means.csv`, `analysis_metadata.csv` and `summary.md` must be byte-identical and `result.json` / `analysis_manifest.json` equal apart from `runtime_seconds`, `created_at` and `git`. On the workstation, the same comparison against the kept `results/motco_analysis/` records (statistics, p-values, rank) before the sweep is run.

**D2. The ladder is `ANALYSIS_FORCED_RANKS = (2, 3, 4, 6, 9, 12)`, a constant.**
Rank 2 is `n_stages − 1`, which MOTCO's stage-supervised rule selects at three stages in its operating studies (median 2, range 2–3 at the Phase 6 design) and the first rank at which `angle` is not degenerate; 3 is the next rank; 4, 6, 9, 12 are the steps of MOTCO's own rank ladder, which makes the two sweeps comparable, and 4 = 2(K − 1) is the one forced rank with a Type I measurement at this design. Rank 1 is excluded by MOTCO (`forced_components ≥ 2`); the CV-selected analysis stands in for it as the reference row, and the manifest says so. The feasibility check (`k ≤ min(n_donors, n_features)`) runs for all ranks before the first run so an infeasible ladder fails without partial output. Cost: a forced run skips the 60 CV fits that dominate the 68 s CV run; expected seconds per rank.
- *Alternative: consecutive ranks 2–6.* Rejected: no comparability with MOTCO's ladder, and the high ranks are where the ladder showed noise directions entering the space.
- *Alternative: 2 and 3 only.* Rejected: it cannot show rank dependence beyond the first two ranks, which is what the sweep is for.
- *Alternative: a `--forced-rank` CLI flag.* Rejected: scientific settings are constants here, never flags; a flag invites choosing ranks after seeing results.

**D3. Same seed and permutation count at every rank; the reference is read, not rerun.**
`ANALYSIS_SEED` and `ANALYSIS_PERMUTATIONS` are reused at every rank, as MOTCO's Type I study did for its forced-rank columns, so every rank permutes the same residual indices and the between-rank differences are measurement differences. The reference row is taken from `results/motco_analysis/<cohort>/result.json` after `_check_reference(cohort_dir, analysis_dir, loaded["inputs"], motco_version)` has verified the five export hashes against `analysis_manifest.json["inputs"]["files"]`, `software.motco` against the installed version, and `measurement.seed` / `measurement.permutations` against the constants; any mismatch is a `ValueError` naming the file or setting and the `analyze` command. The sweep never writes under the analysis root.
- *Alternative: rerun the CV analysis inside the sweep.* Rejected: it would duplicate the primary artifact, cost the CV minute per cohort, and invite the CV row and the kept analysis to diverge.
- *Alternative: a different seed per rank.* Rejected: it adds Monte Carlo spread (SD about 0.015 on these p-values) to a comparison that should only see the rank.

**D4. Output layout.**
`results/motco_rank_sensitivity/<cohort>/` with `rank_02/ … rank_12/` (each a full analysis directory from D1), `rank_sensitivity.csv`, `rank_sensitivity.md` and `rank_sensitivity_manifest.json`. The whole cohort is written under `<cohort>.tmp/` and renamed when every rank and the table are complete, so a partial sweep never looks finished; an existing cohort directory is an error without `--force`. The `RANK_SENSITIVITY_DIR_TEMPLATE = "rank_{:02d}"` keeps directory order equal to rank order.
- *Alternative: `results/motco_analysis/<cohort>/forced/`.* Rejected: `analyze --force` replaces the cohort directory, and the primary artifact should stay as the archived change left it.

**D5. Cross-rank table and summary renderer.**
`_sensitivity_row(record, *, cohort, component_selection, directory)` flattens one record to `cohort, component_selection, rank, {stat}, {stat}_p, {stat}_rejected, {stat}_null_mean, {stat}_null_sd, {stat}_null_q95` for the three statistics, `cv_mean_auroc`, `runtime_seconds`, `dir` (the reference analysis directory for the `cv` row, the `rank_<kk>` name relative to the cohort directory for a forced row, so the table does not depend on `--out-dir`); `rank_sensitivity.csv` is the DataFrame of the reference row followed by the ranks without `runtime_seconds` (the one volatile column; the reproducibility requirement wants the CSV byte-identical across reruns, so runtimes live in the Markdown's run table and in the manifest), written with shortest round-trip floats (`repr`) because pandas' default 16 significant digits do not reproduce every `result.json` value. `render_rank_sensitivity(rows, *, cohort, seed, permutations, alpha)` writes the Markdown with one table per statistic (rank × observed / p / rejected / null mean / sd / q95), a run table (CV AUROC, runtime, directory) and a header naming the seed, permutations, α and the reference rank. `render_analysis_summary` branches on `component_selection`: for `forced`, the `angle` note reads "forced rank k (dimensionality sensitivity; the CV-selected analysis is primary)", the latent block prints "PLS-DA rank: k (`forced`)" and "cross-validation: skipped (rank forced)" instead of the CV line, and `cv_mean_auroc` prints `n/a`. For `cv` records the renderer's output is unchanged, which the D1 byte-identity check covers.

**D6. CLI.**
`sead-sexdiff rank-sensitivity [--cohort {cohort_30,cohort_50,all}] [--input-dir results/motco_input] [--analysis-dir results/motco_analysis] [--out-dir results/motco_rank_sensitivity] [--n-jobs 1] [--force]`, printing `[rank-sensitivity]` progress per rank (rank, runtime, statistics) and the cross-rank table at the end. `--n-jobs` carries the same note as `analyze` (per-worker RRPP seeding), and the manifest records it with a finding when it is not 1.

**D7. A separate dated report.**
`reports/motco-astrocyte-rank-sensitivity-<date>.md`, assembled by a scratch script that pastes each cohort's `rank_sensitivity.md`, with hand-written provenance (MOTCO commit, this repo's revision, seed, permutations, `n_jobs`), the reading rules the spec binds, the forced-rank limitations from MOTCO's reports, and a pointer to the primary report for the covariate block and the feature filtering (unchanged, same inputs by D3). A check script finds every statistic, p-value, null summary and rank from the 14 records (2 references + 12 ranks) in the report text. Two descriptive checks are added if they hold: whether `pls_0` at every forced rank equals the CV run's single component (PLS components are fitted sequentially, so they should), and the `angle` null width across ranks.
- *Alternative: append a section to `reports/motco-astrocyte-2026-10-19.md`.* Rejected: that report is a checked record of the primary analysis at a commit; the sweep has its own provenance and its own run date.

## Risks / Trade-offs

- [A forced-rank rejection gets read as "the" result, or a rank gets picked afterwards] → the ladder is a constant, the CV analysis is the reference row in every table, and the spec fixes the report wording (rank dependence, primary unchanged).
- [No Type I evidence for the adjusted analysis at forced ranks, and none at all for ranks 2, 3, 6, 9, 12 at this design] → stated as a limitation in the report; MOTCO's ladder found no anchor inflation at any rank (unadjusted, n = 1200), which is cited as such, not as a guarantee.
- [Twelve latent columns plus twelve model columns at cells of 9–28 donors] → the OLS has 80 rows and 12 columns, so it is well posed; MOTCO errors on a rank-deficient design, and the null sd per statistic is in the table. If a rank fails, the sweep fails without partial output and the error is reported, not worked around.
- [The refactor changes `analyze` output] → D1's byte-identity check on synthetic data before the real run and the statistics comparison against the kept records on the workstation.
- [The export on the workstation was regenerated after the analysis] → D3's hash check stops the sweep rather than comparing against a stale reference.
- [Data are not on this machine] → tasks group 3 is explicitly a workstation task; everything before it runs anywhere.
